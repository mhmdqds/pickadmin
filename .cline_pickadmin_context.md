## 1. EXECUTIVE SUMMARY

PickAdmin is an enterprise-grade, multi-vendor, multi-business-model delivery and e-commerce platform built on Laravel 12.x. It operates as a digital marketplace connecting Customers, Vendors (Stores), Delivery Drivers, and Administrators across multiple industries.

**Core Business Verticals:**
- Food Delivery (primary)
- Grocery/E-commerce
- Pharmacy/Healthcare
- Parcel/Logistics Delivery
- Vehicle Rental (module)
- Ride Sharing/Taxi (module)
- AI Services (module)

**Architecture Philosophy:** Modular architecture where each business domain is an isolatable module. Hybrid architecture combining Standard MVC, Service Layer (CentralLogics), Repository Pattern, and Module-based development.

**Key Metrics:**
- 124 Eloquent Models | 100+ Database Tables | 200+ Migrations
- 7 Authentication Guards | 30+ Payment Gateways | 8 Active Modules
- 11 CentralLogics Files (~6,000 lines) | 3 Route Files (1,700+ lines)

## 10. EXECUTION FLOW MAPPING

### 10.1 Order Placement Flow

```
[Customer App]
    ↓ POST /api/v1/customer/order/place
[Request]
    ↓ middleware: auth:api, module-check
[OrderController@place_order]
    ↓ Validation (Form Request)
    ↓ Cart retrieval & validation
    ↓ Zone verification
    ↓ Calculate totals (tax, discount, delivery)
[Helpers::product_discount_calculate()]
    ↓ Check Flash Sale (active + stock > 0)
    ↓ Check Store Discount (time-based)
    ↓ Check Product Discount
    ↓ Return highest discount
[Order::create()]
    ↓ Observer: OrderObserver::created()
    ↓ Creates OrderReference record
[OrderPayment::create()]
    ↓ Based on payment_method (COD/Wallet/Digital/Offline)
    
IF Digital Payment:
    ↓ Redirect to payment gateway
    ↓ Gateway processes payment
    ↓ Callback to /payment/{gateway}/callback
    ↓ CSRF bypass for webhooks
    ↓ Calls order_place($data) [app/helpers.php]
    ↓ Updates Order: status='confirmed', payment_status='paid'
    ↓ Decrements StoreSubscription max_order (if applicable)
    ↓ OrderLogic::update_unpaid_order_payment()
    ↓ Helpers::send_order_notification()
    ↓ Sends OrderVerificationMail (if enabled)
    ↓ FCM push notification to vendor

[Database Changes]
    orders: new record
    order_details: line items
    order_payments: payment record
    order_transactions: commission record (on completion)
    wallet_transactions: if wallet used
```

### 10.2 Delivery Assignment Flow

```
[Order Confirmed]
    ↓ Status: confirmed → processing → handover
[Driver App Polling]
    ↓ GET /api/v1/delivery-man/latest-orders
    ↓ Scope: Order::SearchingForDeliveryman()
    ↓ Condition: null delivery_man_id, delivery/parcel type
[Driver Accepts]
    ↓ PUT /api/v1/delivery-man/accept-order
    ↓ Updates Order: delivery_man_id, status='accepted'
[Driver Updates Location]
    ↓ POST /api/v1/delivery-man/record-location-data
    ↓ Creates DispatchDriverLocationJob (Queue)
    ↓ Job broadcasts DeliveryLocationUpdated event
    ↓ WebSocket: Channel 'dm_location_{id}'
    ↓ Customer app receives real-time GPS
[Status Updates]
    ↓ accepted → confirmed → processing → handover → picked_up → delivered
[Completion]
    ↓ OTP verification (if enabled)
    ↓ Status: delivered
    ↓ Creates OrderTransaction (commission calculation)
    ↓ Credits StoreWallet
    ↓ Credits DeliveryManWallet (tips + delivery fee)
```

### 10.3 Subscription Lifecycle Flow

```
[Vendor Registration]
    ↓ /vendor/apply
    ↓ VendorController@store
    ↓ Creates Vendor → Store
[Business Plan Selection]
    ↓ /vendor/business-plan
    ↓ Selects SubscriptionPackage
[Payment]
    ↓ POST /api/v1/vendor/business_plan
    ↓ Redirects to payment gateway
    ↓ Payment success → sub_success() [app/helpers.php]
    ↓ Helpers::subscription_plan_chosen()
    ↓ Creates StoreSubscription (status=1)
    ↓ Creates SubscriptionTransaction
[Daily Check]
    ↓ Store::booted() implicit check
    ↓ If expiry_date <= today:
        - Store: status=0, store_business_model='unsubscribed'
        - StoreSubscription: status=0
[Renewal]
    ↓ POST /api/v1/vendor/package-renew
    ↓ Same payment flow as initial
```

### 10.4 Commission Calculation Flow

```
[Order Delivered]
    ↓ Creates OrderTransaction
[OrderTransaction Fields]
    - order_amount: total order value
    - admin_commission: percentage of order
    - admin_expense: discounts absorbed by admin
    - delivery_fee_comission: admin cut of delivery fee
    - store_amount: net to vendor
    - delivery_man_amount: net to driver
    
[Formula]
    admin_net = admin_commission + admin_expense - delivery_fee_comission
    store_net = order_amount - admin_commission - admin_expense
    driver_net = delivery_fee - delivery_fee_comission + dm_tips

[Settlement]
    ↓ StoreWallet: increment by store_net
    ↓ DeliveryManWallet: increment by driver_net
    ↓ AdminWallet: tracks digital_received, commission_earned
```

```
    ↓ GET /admin/refund/{status}

If Approved:
    ↓ Status: refund_requested → refunded
    ↓ OrderTransaction marked as refunded
    ↓ Customer wallet credited (if wallet payment)
    ↓ StoreWallet debited (store_amount)
If Rejected:
    ↓ Status: refund_requested → refund_request_canceled
```

### 10.6 Wallet Top-up Flow

## 20. BUSINESS INTELLIGENCE LAYER

### 20.1 Core Revenue Streams

| Revenue Stream | Mechanism | Configuration |
|----------------|-----------|---------------|
| **Order Commission** | % of each order | business_settings.admin_commission |
| **Delivery Fee Commission** | % of delivery charge | business_settings.delivery_fee_comission |
| **Subscription Fees** | Monthly vendor plans | subscription_packages table |
| **Flash Sale Admin Cut** | % of flash sale discount | flash_sales.admin_discount_percentage |

### 20.2 Commission Logic

```php
// On order completion:
$order_transaction->order_amount = $order->order_amount;
$order_transaction->admin_commission = ($order_amount * admin_commission%) / 100;
$order_transaction->delivery_fee_comission = ($delivery_fee * delivery_fee_comission%) / 100;
$order_transaction->admin_expense = sum of admin-absorbed discounts;
$order_transaction->store_amount = $order_amount - $admin_commission - $admin_expense;
$order_transaction->delivery_man_amount = $delivery_fee - $delivery_fee_comission + $dm_tips;
```

### 20.3 Subscription Logic

| Business Model | Description | Table Field |
|----------------|-------------|-------------|
| **Commission** | Pay per order % | stores.store_business_model='commission' |
| **Subscription** | Fixed monthly fee | stores.store_business_model='subscription' |
| **Unsubscribed** | Expired/No plan | stores.store_business_model='unsubscribed' |

**Subscription Limits:**
- `max_order`: Number of orders allowed (or 'unlimited')
- `max_product`: Number of products allowed
- `self_delivery`: Can use own drivers
- `chat`: Customer chat feature
- `review`: Review feature

### 20.4 Wallet Logic

| Wallet Type | Owner | Operations | Table |
|-------------|-------|------------|-------|
| **Customer** | User | add_fund, order_payment, refund | wallet_transactions |
| **Vendor** | Store | order_settlement, withdraw | store_wallets |
| **Driver** | DeliveryMan | delivery_earnings, tips, withdraw | delivery_man_wallets |
| **Admin** | Admin | digital_received, commission | admin_wallets |

### 20.5 Settlement Logic

```
Order Complete
    ↓
OrderTransaction created
    ↓
StoreWallet incremented (store_amount)
    ↓
DeliveryManWallet incremented (delivery_man_amount + tips)
    ↓
AdminWallet incremented (commission + digital_received)

Withdraw Request
    ↓
Vendor/Driver requests withdraw
    ↓
Admin approves
    ↓
Disbursement created (if auto-disbursement enabled)
    ↓
Payment sent via configured withdrawal method
```

### 20.6 Loyalty Logic

```
Customer Orders
    ↓
Admin configures loyalty_point_exchange_rate
    ↓
LoyaltyPointTransaction created on eligible orders
    ↓
Customer can:
    - Transfer points to wallet (POST /loyalty-point/point-transfer)
    - Use points for order discount
```

### 24.1 Authentication Strengths

| Aspect | Implementation |
|--------|----------------|

### 24.5 Security Patterns

## 33. FINAL SUMMARY

### 33.1 Project Strengths

- **Modular Architecture**: 8 independent modules via `nwidart/laravel-modules`
- **Multi-Auth System**: 7 separate guards for different user types
- **Payment Flexibility**: 30+ gateway integrations
- **Real-time Features**: WebSocket tracking + Firebase notifications
- **Business Intelligence**: Comprehensive reporting dashboards
- **Subscription Model**: Flexible vendor plans with auto-expiry
- **Multi-language**: Dynamic translation system
- **Wallet System**: Multi-user-type wallet with transactions

### 33.2 Architecture Gaps

- **Monolithic Helpers.php**: 5600+ lines of core logic
- **Empty Scheduler**: No cron jobs defined (relying on model boot)
- **Single Job**: Only 1 queue job defined
- **No Soft Deletes**: Missing on critical models
- **Limited Audit Trail**: Compliance concerns

### 33.3 Critical Business Rules

1. Store subscriptions auto-expire via `Store::booted()`
2. `ZoneScope` filters ALL queries for non-super-admins
3. Commission calculated on order delivery
4. Flash sales override store/product discounts
5. Data masking in demo mode (`APP_MODE=demo`)

### 33.4 Technology Maturity

- Laravel 12.x with PHP 8.2+
- Modern package ecosystem
- OAuth2 API security
- WebSocket real-time features
- Modular development capability
